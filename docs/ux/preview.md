## How to review

1. Open the preview project and step through the screens in the order above; each shows the default state of one screen.
2. For the exact design that implementation builds against, open "Exported default" and the state links (these match the PNGs in `design/stitch/<NNN-slug>/` and the specs in `docs/ux/screens/`).
3. Note decisions per screen (approve, or the changes needed) and record them in `review-log.md`.

## What Stitch could and could not do (MCP)

- Could: create the dedicated preview project, attach the BudgetFlow Satori design system (`assets/9318800711745724949`, same tokens), generate screens there with numbered titles, and give each screen a preview URL by node id.
- Could not copy screens between projects, so the preview copies are regenerations from the same briefs: layout and tokens match, but nav labels, owners and some sample values drift. The exported designs (main project) are the reference.
- Could not rename screens, so main-project screens keep Stitch's automatic titles; use this table for numbering.
- Could not link screens together or add interactions: the MCP has no hotspot, link or flow tool. Previews are static screens, not a click-through flow; move between them with the links above.
- Could not change project visibility or sharing, and `list_screens` returns nothing for the new project type.

## Clickable design preview

Live: **https://narasimhahyland.github.io/budgetflow/** (guided flow starts at https://narasimhahyland.github.io/budgetflow/screens/000a-app-shell--default.html).

Product overview for leadership: **https://narasimhahyland.github.io/budgetflow/overview/**, a one-page, plain-language summary of the finished product (what it brings, features, roles, how it works, what makes it different). It is a single self-contained page in `design/preview/overview/index.html`, published with the preview and linked from its index. The site is public, so the page names only generic system categories, never internal tools, figures or people.

The exported screens and states above are also published as a clickable design preview: sidebar items, primary buttons, table rows and dialog triggers open the matching screen or state, and a bar on every page switches states and steps through the core journey. It is built from `design/preview/` from the Stitch exports and published from the `gh-pages` branch with GitHub Pages (the design preview only; the app itself is never deployed to Pages). Details are in [design/preview/README.md](../../design/preview/README.md). States whose HTML could not be saved from Stitch are shown as their exported image with hotspots.

To rebuild and republish when new screens merge into `design/stitch/`:

1. Save each new state's Stitch HTML: `get_screen`, then `download_file` on `htmlCode.name`, then `node design/preview/build.mjs import --from <result file> --screen <NNN-slug> --state <state>`. For states without HTML, record label positions on macOS with `swift design/preview/ocr.swift <exported png> design/preview/ocr/<NNN-slug>--<state>.json`.
2. Add the screen to `areas`, `journey` and `links` in `design/preview/links.json`; `node design/preview/build.mjs report` lists what each page links to.
3. Run `design/preview/deploy.sh`; it builds `design/preview/dist`, publishes only that folder and enables Pages if needed.
