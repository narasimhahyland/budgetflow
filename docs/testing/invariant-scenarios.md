# Invariant-to-scenario map

Every domain and ledger invariant is proven by an API scenario in `apps/api-e2e` (HTTP against the running API, real Keycloak tokens, real Postgres). A change that adds or alters an invariant updates this table and the scenario in the same change. Status is `planned (Pn)` until the scenario exists and passes, then `passing`; `passing (P1 part)` means the Phase 1 part passes and the rest lands in the named phase. Rules: `.cursor/rules/domain-invariants.mdc`, `.cursor/rules/ledger-accounting.mdc`, `.cursor/rules/testing-functional.mdc`. Evidence: `evidence/phase-01/` (ledger hardening after the Phase 1 domain review: `evidence/phase-01/ledger-hardening/`).
