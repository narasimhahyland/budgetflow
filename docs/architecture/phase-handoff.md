## Rules for every phase agent

1. **Owned paths only.** Each phase below lists the paths it owns. Shared surfaces belong to the integrator (`git-worktree-workflow.mdc`): `package.json`, lockfile, `nx.json`, `tsconfig.base.json`, `eslint.config.mjs`, `.stylelintrc.mjs`, `libs/contracts/src/lib/{common,endpoint,endpoints,registry}.ts` and `index.ts`, `libs/api/db/**`, `libs/domain/src/index.ts` and `authorization/policy.ts`, `apps/api/src/app/app.module.ts`, `apps/worker/src/app/worker.module.ts`, `apps/api/src/seed/extensions.ts`, `apps/web/src/app/**`, `libs/web/ui/**`, `libs/web/data-access/**`, `apps/web-e2e/visual/screens.json`, `docs/testing/invariant-scenarios.md`, `infra/**`, `.cursor/**`, `.github/**`. Put requested changes to them in your report.
2. **Contracts.** New domain: `libs/contracts/src/lib/domains/<domain>.ts` with `named()` schemas and a `<domain>Endpoints` map; the integrator adds one spread line in `endpoints.ts` and one export in `index.ts`, then runs `npx nx run contracts:openapi`. Within a phase changes are additive (optional fields, new endpoints); renames need a version bump and user approval.
3. **Schema and migrations.** Add tables in a new schema file `libs/api/db/src/schema/<area>.ts` (export it from `schema/index.ts`); generate with `npx nx run db:generate -- --name <verb_noun>` (never `push`). Every new tenant table needs, in the same migration, `ENABLE` + `FORCE ROW LEVEL SECURITY` and `CREATE POLICY tenant_isolation ... USING (tenant_id = app_current_tenant()) WITH CHECK (...)`; append-only tables also need `REVOKE UPDATE, DELETE, TRUNCATE ... FROM bf_app, bf_worker` and the `app_reject_mutation()` triggers. `db/rls-policies.spec.ts` fails otherwise. Merged migrations are immutable; during a wave the integrator assigns the final migration number in merge order and regenerates the drizzle journal.
4. **Money.** Post only through `libs/domain` posting builders and `LedgerService.post` inside `CommandRunner.run` (idempotency key, ordered locks via `LedgerReads.lockBudgets`, one `AuditService.append`). Never write `ledger_*` tables directly; never add update paths.
5. **Authorization.** Use `PolicyService.assert` / `can`. New actions go into `ACTIONS` and `ROLE_GRANTS` (integrator) and the matrix in [authorization.md](authorization.md) is regenerated.
6. **API wiring.** A new module is `libs/api/<module>` (tags `type:api-module`, `scope:api`) with `<X>Module` and `<X>ApiModule`; the integrator imports `<X>ApiModule` in `AppModule` (and `<X>Module` in `WorkerModule` for jobs). Side effects go through `outbox_messages`; the worker registers queues in `JobsService`.
7. **Seed.** Data in `libs/seed/src/lib/<area>.ts` (fixed ids from `seedId(prefix, n)`, pick an unused 8-digit prefix and record it in the table below), runner in `apps/api/src/seed/<area>.ts` registered in `SEED_EXTENSIONS`. Idempotent: `ON CONFLICT DO NOTHING` or real commands with fixed `seed:` idempotency keys. New users: add to `libs/seed/src/lib/roles.ts` and regenerate the realm (`npx tsx --tsconfig libs/seed/tsconfig.lib.json infra/keycloak/generate-realm.ts`).
8. **Tests.** Own `apps/api-e2e/src/<area>/` and `apps/web-e2e/src/<area>/`. Scenarios create their own budgets through the API (see `apps/api-e2e/src/support/factory.ts`) and never mutate the seeded reference tree; destructive checks run only in the Initech Sandbox tenant and restore it. Ask the integrator to add invariant rows and `screens.json` entries.
9. **Web.** Phase 2 creates `libs/web/ui`, `libs/web/data-access` (on `createApiClient`) and `libs/web/shell`. Each screen group is `libs/web/features/<group>` (tags `type:feature`, `scope:web`) exporting `Routes`; features never import each other; the integrator wires lazy routes in `apps/web`. Light theme only.
10. **Done** means `/functional-check` and `scripts/gate.sh` green, evidence under `evidence/<phase-id>/`.

Reserved seed id prefixes: `10`-`24` tenancy and finance, `30`-`35` org, `40`-`42` people and memberships, `50` Keycloak subjects, `60`-`68` categories, plan, reason codes, DoA, flags, templates, `70` budgets. Next free: `71` (P4), `72`-`76` (P5), `77`-`79` (P6), `80`+ later phases.

## Wave 2 parallel split (P4, P5, P6)

If Phases 4-6 run in parallel, scopes stay disjoint: P4 owns `libs/api/budgets` and `libs/web/features/budgets`; P5 owns the new modules listed above and their features; P6 owns `libs/api/actuals` and `libs/web/features/accounting`. Commitment posting is shared through `postCommitmentMovement` in `libs/domain` (already present), so P5 and P6 do not edit each other's modules: P5 creates and approves commitments, P6 consumes them through an exported `CommitmentsService` from P5's `libs/api/spend` (request the export in the report if it is missing). Merge order: P4, then P5, then P6; the integrator renumbers migrations in that order.

## Known follow-ups from Phase 1

- Phase 1 creates budgets directly as `active`; the submit and approve flow is Phase 4.
- Cost center is optional on every budget today; Phase 4 enforces it on leaf budgets at the first commitment.
- Isolated Testcontainers runs (`API_E2E_ISOLATED=1`) and the migration-from-previous-release check are wired as dependencies but not yet used by a scenario; Phase 17 adds them.
