### Outbox event contract: `budget.control_changed` (Phase 5 consumes)

One message per affected budget (a cascade emits one per budget below, with `cascadeFromBudgetId`), published in the same transaction as the control change.

| Field                                                       | Meaning                                                                                                                                                                                                                                                         |
| ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `eventId`                                                   | Unique id (idempotency key for the consumer)                                                                                                                                                                                                                    |
| `tenantId`, `budgetId`, `budgetName`                        | The budget whose control changed                                                                                                                                                                                                                                |
| `action`                                                    | `frozen`, `unfrozen`, `reduced`, `set_to_zero`, `restored`                                                                                                                                                                                                      |
| `pendingRequestPolicy`                                      | `cancel` (set to zero: cancel pending requests with the reason and notify), `hold` (frozen), `release` (unfrozen, restored), `return_unfit` (reduced: return the requests in `unfitRequestIds` to their requesters with the reason "budget reduced" and notify) |
| `previousStatus`, `status`                                  | Budget status before and after                                                                                                                                                                                                                                  |
| `reasonCode`, `reason`                                      | Reason code (null for unfreeze and restore) and typed reason                                                                                                                                                                                                    |
| `cascadeFromBudgetId`                                       | The budget the user acted on when this one changed by cascade (null otherwise)                                                                                                                                                                                  |
| `journalId`                                                 | Reduction journal (null for freeze, unfreeze and restore)                                                                                                                                                                                                       |
| `authorizedBeforeMinor`, `authorizedAfterMinor`, `currency` | Authorized amount before and after                                                                                                                                                                                                                              |
| `actorPersonId`, `occurredAt`                               | Who and when (UTC ISO 8601)                                                                                                                                                                                                                                     |
| `unfitRequestIds`                                           | Reduce: pending requests (open pre-encumbered commitments linked to a request) that no longer fit, most recently submitted first; empty otherwise                                                                                                               |

Phase 5 must not post new commitments against a budget whose status fails `acceptsNewActivity`; completing existing commitments (encumbered to actual, releases) stays allowed under every control.

### Phase 4 review follow-up (fix/p4-review)

- **Roll-up utilization and alerts.** Utilization on budget detail, the hierarchy and the summary is `(encumbered + actual of the budget and everything below it) / authorized`. Owner alerts use the same roll-up through `ThresholdAlerts` (`libs/api/ledger`): read `utilizations(tx, budgetIds)` after locking and call `emit(tx, tenantId, before, budgetIds)` after posting. Manual journals and reversals already do; Phase 5 (commitments) and Phase 6 (actuals) call it when they post, so a parent's owner is alerted by spend in its children.
- **Company-wide Available** subtracts held money: authorized − held − pre-encumbered − encumbered − actual over the subtree (`BudgetSummary.held` added).
- **Sibling transfers.** The owner of both sibling budgets transfers directly (`budget.allocate` on both, same parent); the owner of the common parent and finance still can. Routing other sibling transfers to the parent owner as a request is **Phase 7** (approvals).
- **Reduce below pending requests.** `pendingRequestPolicy` for `reduced` is now `return_unfit` with `unfitRequestIds` on the event, the preview (`ControlImpact`) and the result. Phase 5's `budget.control_changed` consumer returns those requests to their requesters (cancelled with the reason "budget reduced", pre-encumbrance released, requester emailed); `requests/controls.spec.ts` proves it.
- **Allocation grid Drafts.** A new grid row without an owner is created as an ownerless Draft (line outcome `draft`) that receives nothing; activation refuses a Draft without an owner.
- **Phase 4 follow-up part 2 (`fix/p4-followup-part2`, migration `0007_p4_plan_baseline`):**
  - _Approved plan versions are immutable_ (`plan_version_lines_immutable` trigger allows only linking `budget_id` from null on non-draft versions; `POST /api/budgets` for a root links an existing unlinked line and otherwise answers `PLAN_REVISION_REQUIRED`) and _new money needs Finance Admin and CEO_ (`PLAN_SIGNOFF_REQUIRED`, `SELF_APPROVAL`; second Finance Admin seed user `finance-admin-2`; root factories in `apps/api-e2e` and `apps/web-e2e` create roots through additive plan revisions whose linked lines join the year's tie-out).
  - _Contingency reserve as its own root_ under Hyland (`EX-RESERVE`, seeded with its own plan line) and an approved release that moves money from that root into a program budget (the only cross-root move).
  - _Per-head rate per month_: amount = USD rate × eligible headcount (prorated) × months left in the fiscal year from the as-of month; a monthly true-up posts rate × headcount change × months left. Labeled "Rate per eligible employee per month (USD)".
- **One audit entry per command.** `BudgetsService.createInTx` / `allocateInTx` and `ControlsService.transferInTx` take `audit: false` when the calling command writes the single entry itself (grid, per-head, request decisions, roll forward, plan apply).

### Commitments: what Phase 6 consumes from Phase 5

Import `SpendModule` from `@bf/api/spend` and use `CommitmentsService` inside your command transaction (`tx` from `CommandRunner.run`, `PostCtx` = actor, command name, request id, idempotency key):

- `consume(tx, ctx, { commitmentId, amount, actualId? })`: a matched actual moves encumbered to actual at the commitment's stored rates, pro rata across its funding lines; the last remainder relieves exactly what was posted. Returns `{ journalIds, consumedBudgetMinor, status }`. Allowed under every budget control.
- `release(tx, ctx, commitmentId)`: releases what is left of an encumbered or partially consumed commitment (event lines back to their funding sources' earmarks, request lines to the budget). Returns `{ journalIds, releasedBudgetMinor }`.
- `row(tx, id, lock?)` reads a commitment; `listForEvent` / `views` return the contract shape.

Every posting goes through `PostingSupport.post`, which raises owner threshold alerts (`BudgetViews.emitThresholds`); the worker emails the owner on `budget.threshold_crossed`. The worker consumes `budget.control_changed` (`BudgetControlConsumer`): set to zero cancels waiting requests and Inter-Director Budget Contribution Requests with the reason "budget set to zero" and emails the requesters, freeze holds them, unfreeze and restore release them, a reduction returns the requests listed in `unfitRequestIds` ("budget reduced") and keeps the rest.

How the guarantees are enforced, in one place each:

- **Scoped retrieval.** `AiRetrieval` is the only way the AI layer reads tenant data. It runs inside
  `withTenant` (so RLS applies) and then filters every candidate row through `PolicyService.can` for
  the asking user. A record the asker could not open in the UI is never retrieved, never sent and
  never cited, and the scope that was applied is recorded on the query-log row.
- **Data minimization.** `minimize()` keeps only the field names a feature's allow-list names
  (`ALLOWED_FACT_FIELDS`) and drops anything that looks like personal data or a credential whatever
  it is called. The surviving field names go on the query-log row, so an auditor can see exactly what
  left the server, and 113a shows the same list in the turn-on dialog.
- **Figures.** Every amount shown comes from `BudgetViews` or another reconciled read model. The
  figure guard rejects any model-written sentence containing a number that was not in the retrieved
  facts, and the gateway then discards the whole output (`discarded_unreliable`).
- **Nothing is applied by AI.** `AiSuggestionsService.decide` records `accepted` only after it finds
  the audit entry that the real command wrote on the applied record (and, for matching, only once the
  spend line is no longer unmatched). There is no privileged apply path.
- **Evaluation.** `EVAL_SETS` measures each feature against a published threshold using the fake
  provider; results land in `ai_evaluation_runs`, and an anomaly kind below its threshold stops
  raising new flags.

## Rules for every phase agent

1. **Owned paths only.** Each phase below lists the paths it owns. Shared surfaces belong to the integrator (`git-worktree-workflow.mdc`): `package.json`, lockfile, `nx.json`, `tsconfig.base.json`, `eslint.config.mjs`, `.stylelintrc.mjs`, `libs/contracts/src/lib/{common,endpoint,endpoints,registry}.ts` and `index.ts`, `libs/api/db/**`, `libs/domain/src/index.ts` and `authorization/policy.ts`, `apps/api/src/app/app.module.ts`, `apps/worker/src/app/worker.module.ts`, `apps/api/src/seed/extensions.ts`, `apps/web/src/app/**`, `libs/web/ui/**`, `libs/web/data-access/**`, `apps/web-e2e/visual/screens.json`, `docs/testing/invariant-scenarios.md`, `infra/**`, `.cursor/**`, `.github/**`. Put requested changes to them in your report.
2. **Contracts.** New domain: `libs/contracts/src/lib/domains/<domain>.ts` with `named()` schemas and a `<domain>Endpoints` map; the integrator adds one spread line in `endpoints.ts` and one export in `index.ts`, then runs `npx nx run contracts:openapi`. Within a phase changes are additive (optional fields, new endpoints); renames need a version bump and user approval.
3. **Schema and migrations.** Add tables in a new schema file `libs/api/db/src/schema/<area>.ts` (export it from `schema/index.ts`); generate with `npx nx run db:generate -- --name <verb_noun>` (never `push`). Every new tenant table needs, in the same migration, `ENABLE` + `FORCE ROW LEVEL SECURITY` and `CREATE POLICY tenant_isolation ... USING (tenant_id = app_current_tenant()) WITH CHECK (...)`; append-only tables also need `REVOKE UPDATE, DELETE, TRUNCATE ... FROM bf_app, bf_worker` and the `app_reject_mutation()` triggers. `db/rls-policies.spec.ts` fails otherwise. Merged migrations are immutable; during a wave the integrator assigns the final migration number in merge order and regenerates the drizzle journal.
4. **Money.** Post only through `libs/domain` posting builders and `LedgerService.post` inside `CommandRunner.run` (idempotency key, ordered locks via `LedgerReads.lockBudgets`, one `AuditService.append`). Never write `ledger_*` tables directly; never add update paths.
5. **Authorization.** Use `PolicyService.assert` / `can`. New actions go into `ACTIONS` and `ROLE_GRANTS` (integrator) and the matrix in [authorization.md](authorization.md) is regenerated.
6. **API wiring.** A new module is `libs/api/<module>` (tags `type:api-module`, `scope:api`) with `<X>Module` and `<X>ApiModule`; the integrator imports `<X>ApiModule` in `AppModule` (and `<X>Module` in `WorkerModule` for jobs). Side effects go through `outbox_messages`; the worker registers queues in `JobsService`.
7. **Seed.** Data in `libs/seed/src/lib/<area>.ts` (fixed ids from `seedId(prefix, n)`, pick an unused 8-digit prefix and record it in the table below), runner in `apps/api/src/seed/<area>.ts` registered in `SEED_EXTENSIONS`. Idempotent: `ON CONFLICT DO NOTHING` or real commands with fixed `seed:` idempotency keys. New users: add to `libs/seed/src/lib/roles.ts` and regenerate the realm (`npx tsx --tsconfig libs/seed/tsconfig.lib.json infra/keycloak/generate-realm.ts`).
8. **Tests.** Own `apps/api-e2e/src/<area>/` and `apps/web-e2e/src/<area>/`. Scenarios create their own budgets through the API (see `apps/api-e2e/src/support/factory.ts`) and never mutate the seeded reference tree; destructive checks run only in the Initech Sandbox tenant and restore it. Ask the integrator to add invariant rows and `screens.json` entries.
9. **Web.** Phase 2 creates `libs/web/ui`, `libs/web/data-access` (on `createApiClient`) and `libs/web/shell`. Each screen group is `libs/web/features/<group>` (tags `type:feature`, `scope:web`) exporting `Routes`; features never import each other; the integrator wires lazy routes in `apps/web`. Light theme only.
10. **Done** means `/functional-check` and `scripts/gate.sh` green, evidence under `evidence/<phase-id>/`.

## Wave 2 parallel split (P4, P5, P6)

If Phases 4-6 run in parallel, scopes stay disjoint: P4 owns `libs/api/budgets` and `libs/web/features/budgets`; P5 owns the new modules listed above and their features; P6 owns `libs/api/actuals` and `libs/web/features/accounting`. Commitment posting is shared through `postCommitmentMovement` in `libs/domain` (already present), so P5 and P6 do not edit each other's modules: P5 creates and approves commitments, P6 consumes them through an exported `CommitmentsService` from P5's `libs/api/spend` (request the export in the report if it is missing). Merge order: P4, then P5, then P6; the integrator renumbers migrations in that order.

## Known follow-ups from Phase 8

- **`type:ui` may now depend on `type:data-access`.** The shared discussion box (`libs/web/ui/src/lib/discussion-box.ts`, `discussion-panel.ts`) is a connected component: it loads and posts comments itself. Feature libs never import each other, so it went into `libs/web/ui` and `eslint.config.mjs` added `type:data-access` to what `type:ui` may depend on. The relaxation applies to every UI library, not just this one. The alternative to revisit is making the discussion box presentational (inputs and outputs only) and keeping the connected wrapper in a feature lib, which restores the original boundary.
- **`.bf-list__item` is content-box.** In `libs/web/ui/src/styles/page-layout.scss` it has `width: 100%` with 20px side padding and no `box-sizing: border-box`, so it overruns its card. Phase 8 patched it locally on the notification settings screen (`libs/web/features/mobile/src/lib/notification-settings.page.ts`) instead of globally; the shared stylesheet is an integrator surface and the fix moves the visual baselines of every screen that uses the class, which then have to be re-recorded.
