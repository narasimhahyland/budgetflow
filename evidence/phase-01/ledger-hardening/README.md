# Phase 1 ledger hardening — functional evidence

Fixes for the defects a domain-invariant review found in the merged Phase 1 ledger (main `e32ed3e`). Every reviewer probe was first reproduced on this branch's own stack, then turned into a permanent API scenario that now passes.

- Stack: `scripts/stack.sh reset` in the `fix/p1-ledger-hardening` worktree (ports +30: API 3030, Keycloak 8110, Postgres 5462), deterministic seed, real Keycloak tokens per role.
- Roles used: ceo, finance-admin, finance-controller, budget-owner, regional-manager, employee, auditor, sandbox-admin; Globex ids as the foreign tenant.
- Commands: `scripts/gate.sh` (all modes, `gate-summary.txt`); `npx playwright test -c apps/api-e2e/playwright.config.ts` (`functional-api.txt`, 79 scenarios: the 56 existing plus 23 new); the reviewer's probe specs before and after the fix (`probes-before.txt`, `probes-after.txt`).
- API responses (tokens redacted): `api/`.

## Changed expectations in existing scenarios

Two existing assertions changed because the rounding rule changed on purpose (no check was weakened):

- `budgets/over-allocation.spec.ts`: INR 83,250.84 now costs the parent USD 1,000.02 (rounded up), so the rejection names `requestedMinor` 100,002 instead of 100,001.
- `ledger/fx-triplet.spec.ts`: USD 10.01 now credits a JPY child JPY 1,501 (rounded down) instead of 1,502. Half-even at the line stays proven on non-hierarchy lines in the same spec (JPY 1.5 → 2, JPY 4.5 → 4).
