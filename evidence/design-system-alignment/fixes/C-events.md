## Shared requests (not done here)

1. **Visual QA harness false positive.** `scripts/visual/capture.mjs` treats any on-screen scroller ≥ 50 % of the viewport height as the page, so a tall `.bf-table-scroll` that scrolls sideways _by design_ is reported as blocking page overflow (seen on 046/047/049/047a/051a before the layout fixes). Suggest skipping scrollers whose `overflow-x` is `auto|scroll` and whose child is a table, or only measuring the shell content box.
2. **Shell breadcrumbs** (`libs/web/shell/src/lib/shell.ts:156`): support a parent crumb (e.g. route `data: { crumbs: [{ label: 'Events', routerLink: '/events' }] }`) so event pages read Home › Events › <event>.
3. **`sat-navigation-tabs` wraps** to 2–3 rows at 412 px instead of scrolling; changing that needs a Satori option (no internals override).
4. **API**: dashboard cap definition and "100% funded" text (043); "minor units" message (quotes.service.ts:89); truncated contribution term (approvals.service.ts:2061); plain-English audit summaries (050); entity/total data for 049; Actual/blocked flags on `EventSummary` (044).
5. **Sub-page Scorecard tab** shows on sub-pages regardless of status (only the detail page knows the status); passing the status to each sub-page view would let `bf-event-tabs` hide it consistently.
