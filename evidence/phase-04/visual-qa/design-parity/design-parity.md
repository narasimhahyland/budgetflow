# Phase 4 design parity

`scripts/visual/design-parity.mjs` compared 30 desktop states with their approved Stitch exports in `design/stitch/`. Every row is flagged "inspect closely" because the mockups use different sample data (INR figures, other people and programs), a different navigation set and, for dialogs, no page scrim behind the dialog; dialog states therefore sit at 43-72% pixel mismatch and pages at 15-28%. Each side by side was inspected; eight representative ones are kept here, and the full set (with diffs) stays in `tmp/evidence/phase-04/design-parity/` locally.

| Screen                                    | Parity                                                           | Deviation and reason                                                                                                                                                                                                                                       |
| ----------------------------------------- | ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 019 Budget list                           | Layout, filters and columns match                                | All amounts in USD (binding decision: one company, USD budgets).                                                                                                                                                                                           |
| 020 Create budget, 020b Templates         | Form sections match                                              | Program templates hold per-head defaults (rate, eligibility, proration) as the plan asks.                                                                                                                                                                  |
| 020a Plan import                          | Three steps, column mapping and row review match                 | Validate / Create draft version / Close sit in the import card header so the page does not jump when validation results appear. Plan lines are edited by re-importing or copying a version, not inline.                                                    |
| 021 Budget details                        | Header, KPI cards, lifecycle spectrum and governance panel match | Commitments, currency and audit-trail panels are Phase 5, 6 and 11 content; the page shows tabs (overview, children, phasing, limits, requests, versions, history, ledger) instead. Rare actions (transfer, freeze, set to zero) sit in "More actions".    |

The grid only raises amounts; lowering uses Reduce (floor and destination). |
